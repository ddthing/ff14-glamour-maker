# FF14 Glamour Maker 균형 리팩터링 기반 설계

## 1. 목적

P0–P2에서 확보한 데이터 완전성, 접근성, 내보내기 복구성, 초기 번들 개선을 유지하면서 다음 문제를 해결한다.

- 상태 변경 직후 공유하면 500ms URL 반영 지연 때문에 이전 링크가 복사될 수 있다.
- 첫 장비 검색은 12.98MB 데이터 다운로드 이후 시작되어 네트워크 환경에 따라 체감 지연이 크다.
- 초기화와 프리셋 삭제를 실수로 실행했을 때 복구할 수 없다.
- 스킵 링크, 크롭 모달 스크롤 경계, 동적 이미지 크기 명시가 부족하다.
- 검색 제어와 패널 액션이 큰 UI 컴포넌트 안에 결합돼 후속 Web Worker·상태 저장소 전환이 어렵다.

이번 단계는 A안인 안전성 중심의 균형 리팩터링을 수행한다. Web Worker와 Zustand 도입은 범위에서 제외하지만, 나중에 소비자 컴포넌트를 바꾸지 않고 내부 구현을 교체할 수 있는 경계를 만든다.

## 2. 설계 원칙

1. 공개 URL 형식과 기존 프리셋 형식은 변경하지 않는다.
2. 아이템 및 Facewear의 KO·EN·JA 원문과 부위 분류 결과를 변경하지 않는다.
3. 사용자 행동으로 시작되는 작업은 이벤트 핸들러에서 실행한다.
4. 비동기 데이터 접근, 공유 URL 생성, 실행 취소 상태는 UI에서 분리해 단위 테스트가 가능하게 한다.
5. 새 전역 상태 라이브러리나 검색 라이브러리는 도입하지 않는다.
6. 구조 분리는 현재 문제를 해결하는 범위까지만 수행한다.

## 3. 변경 설계

### 3.1 공유 링크 정확성

`features/glamour`에 현재 `AppState`와 `Location`의 경로 정보를 받아 공유 URL을 생성하는 순수 함수를 둔다. 함수는 `encodeStateHash(state)`를 직접 사용하므로 `useUrlState`의 500ms 반영 대기와 무관하게 항상 현재 상태를 포함한다.

`ControlPanel`의 복사 동작은 `window.location.href`를 그대로 복사하지 않고 이 함수를 사용한다. 성공·실패 UI는 현재 동작을 유지한다.

테스트는 다음을 고정한다.

- 기존 origin, pathname, search를 보존한다.
- 전달된 최신 상태가 해시에 포함된다.
- 현재 브라우저 해시가 오래됐더라도 생성 결과에는 영향을 주지 않는다.

### 3.2 검색 데이터 사전 로드 경계

`features/search`는 다음 인터페이스를 제공한다.

- `loadSearchItems(slot)`: 데이터가 필요할 때 기다려 결과를 반환한다.
- `preloadSearchItems(slot)`: 사용자 의도가 확인된 시점에 같은 캐시를 미리 시작하고 오류는 다음 실제 검색이 재시도할 수 있도록 정리한다.

검색 입력의 `focus`와 포인터 진입은 현재 부위 데이터의 사전 로드를 시작한다. 얼굴 소품은 Facewear JSON만, 나머지 부위는 장비 JSON만 요청한다. 단순 페이지 진입에서는 어느 데이터도 요청하지 않는다.

이 경계는 이후 C안에서 내부 로더를 Web Worker 클라이언트로 교체할 수 있게 한다. `ItemSearchInput`과 `useFF14Search`는 Worker 여부를 알지 못한다.

### 3.3 실행 취소 가능한 파괴적 동작

브라우저 기본 확인창 대신 패널 하단의 기존 상태 메시지 영역을 재사용해 5초 실행 취소를 제공한다.

- 전체 장비 초기화: 실행 전 장비 스냅샷을 한 개 보관한다.
- 프리셋 삭제: 삭제한 프리셋과 원래 순서를 보관한다.
- 새 파괴적 동작이 시작되면 이전 실행 취소 항목은 확정하고 최신 한 건만 보관한다.
- 실행 취소 버튼은 키보드로 접근 가능하고 상태 변경은 `aria-live="polite"`로 알린다.

프리셋 저장소에는 `restorePreset(preset, index)` 기능을 추가한다. 저장 실패 시 성공처럼 표시하지 않고 기존 오류 메시지 경계를 통해 알린다.

### 3.4 접근성 보완

- 문서 첫 포커스 지점에 본문으로 이동하는 스킵 링크를 추가하고 `main`에 안정적인 ID를 부여한다.
- 크롭 모달에 `overscroll-behavior: contain`을 적용한다.
- 캐릭터 사진과 장식용 배경 이미지에 렌더링 기준 `width`·`height`를 명시한다.
- 복사·저장 버튼의 장식 아이콘은 보조 기술에서 숨긴다.
- 기존 전역 `focus-visible`과 reduced-motion 규칙은 유지한다.

### 3.5 컴포넌트 책임 분리

이번 단계에서는 전면 재구성 대신 아래 두 경계만 만든다.

- `useShareLink`: 링크 생성, 클립보드 호출, 성공·실패 및 타이머 정리 담당
- `useUndoAction`: 최신 실행 취소 항목 하나의 등록, 만료, 실행, 언마운트 정리 담당

`ControlPanel`은 표시와 이벤트 연결만 담당한다. 검색 데이터 소스는 `loadSearchItems` 인터페이스 뒤에 유지한다. `InfoPanel`의 시각 구조 분리는 출력 픽셀 회귀 위험 때문에 이번 범위에서 제외한다.

## 4. 데이터 흐름

### 공유

1. 사용자가 링크 복사를 누른다.
2. `useShareLink`가 현재 `AppState`로 공유 URL을 즉시 생성한다.
3. 클립보드에 기록한다.
4. 성공 또는 재시도 가능한 실패 상태를 패널에 표시한다.

### 검색

1. 사용자가 검색 입력에 포커스하거나 포인터를 올린다.
2. `preloadSearchItems(activeSlot)`이 해당 데이터 캐시를 시작한다.
3. 입력 debounce가 끝나면 `loadSearchItems(activeSlot)`이 같은 Promise를 재사용한다.
4. 기존 부위 필터, 다국어 점수, 결과 제한 로직을 그대로 실행한다.

### 실행 취소

1. 파괴적 동작 전에 복원 스냅샷을 만든다.
2. 동작을 적용하고 5초 실행 취소 메시지를 표시한다.
3. 사용자가 실행 취소하면 스냅샷을 복원한다.
4. 시간이 만료되거나 새 동작이 시작되면 스냅샷을 폐기한다.

## 5. 오류 처리

- 검색 preload 실패는 콘솔 오류로 중복 보고하지 않고 캐시를 비워 실제 검색에서 재시도한다.
- 실제 검색 실패는 기존 한·영·일 오류 문구를 표시한다.
- 클립보드 실패는 현재 상태를 보존하고 다시 시도 가능한 메시지를 표시한다.
- localStorage 쓰기 실패는 프리셋 UI 상태를 성공으로 확정하지 않는다.
- 실행 취소 타이머는 훅 언마운트 시 정리한다.

## 6. C안으로의 확장 경로

### Web Worker 검색

`loadSearchItems`와 검색 함수의 호출 계약을 유지한 채 내부를 Worker 메시지 요청으로 교체한다. UI 컴포넌트는 변경하지 않는다. 데이터 버전과 요청 세대 번호를 Worker 프로토콜에 추가한다.

### Zustand 상태 관리

현재 `AppState`와 기능 액션을 먼저 feature 함수와 훅으로 분리한다. 이후 `useUrlState` 어댑터 대신 Zustand store 어댑터를 연결하고 URL 직렬화는 store 구독자로 이동한다. 컴포넌트 props는 한 번에 바꾸지 않고 기능별 selector로 점진 전환한다.

### 컴포넌트 추가 분리

출력 픽셀 스냅샷 또는 시각 회귀 테스트를 확보한 뒤 `InfoPanel`, `CanvasItemRow`, `CropModal`을 표현 단위로 나눈다. 시각 회귀 기반이 없을 때는 분리 자체를 목적으로 수정하지 않는다.

## 7. 테스트와 검증

### 단위 테스트

- 최신 상태 공유 URL 생성과 기존 경로 보존
- 장비와 Facewear preload의 선택 로딩, 캐시 공유, 실패 후 재시도
- 실행 취소 등록, 최신 한 건 유지, 만료, 복원
- 프리셋 삭제 후 원래 순서 복원

### 기존 회귀 테스트

- URL codec round trip
- 모든 지원 부위 및 Facewear 데이터 완전성
- KO·EN·JA 전체 이름 검색
- 검색 요청 세대와 결과 제한
- 내보내기 실패 후 DOM 복원

### 완료 검증

- `npm run test`
- `npm run lint`
- `npm run build`
- 빌드 HTML이 아이템 JSON과 무거운 기능 청크를 preload하지 않는지 확인
- 키보드 스킵 링크, 검색, 실행 취소 흐름 확인
- 사용자 소유의 `AGENTS.md`, `page.css`, `page2.html`은 변경하거나 커밋하지 않음

## 8. 완료 조건

1. 상태 변경 직후 복사한 링크가 최신 상태를 복원한다.
2. 첫 화면에서는 아이템 JSON을 요청하지 않고 검색 의도 시 해당 데이터만 미리 요청한다.
3. 전체 초기화와 프리셋 삭제를 5초 안에 되돌릴 수 있다.
4. 스킵 링크, 모달 overscroll, 이미지 크기 및 장식 아이콘 접근성 누락이 해소된다.
5. 공개 URL·프리셋 형식과 다국어 아이템 데이터가 유지된다.
6. 후속 Web Worker와 Zustand 전환이 공개 UI 컴포넌트 재작성 없이 가능하다.
7. 전체 테스트, 린트, 타입 검사, 프로덕션 빌드가 통과한다.
