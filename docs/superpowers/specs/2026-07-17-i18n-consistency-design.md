# 다국어 표시 일관성 보완 설계

## 목표

한국어, 영어, 일본어 전환 시 공통 내비게이션과 장비 선택 UI가 현재 언어를 일관되게 사용하도록 한다. 공개 URL, 저장 데이터, 레이아웃, 아이템 분류 규칙은 변경하지 않는다.

## 확인된 문제

- `Header`의 내비게이션 접근성 이름이 한국어로 고정되어 있다.
- `Footer`의 내부 링크 이름이 한국어로 고정되어 있다.
- `SlotButton`의 선택 아이템 접근성 이름이 기본 한국어 이름을 직접 사용한다.

## 선택한 접근

공통 UI 문자열은 i18next 리소스에 추가하고, 아이템 이름은 기존 `getLocalizedItemNames`를 재사용한다.

- `common.main_navigation`과 푸터 링크용 번역 키를 한국어, 영어, 일본어에 같은 구조로 추가한다.
- `Header`와 `Footer`는 하드코딩된 문자열 대신 `t(...)`를 사용한다.
- `SlotButton`, `EquipmentTab`, `ItemSearchInput`은 현재 `i18n.language`와 `getLocalizedItemNames`로 선택 아이템과 검색 결과의 주·보조 이름을 만든다.
- 브랜드명, 외부 Support 링크, 페이지 본문 번역은 이번 범위에 포함하지 않는다.

## 데이터 흐름

1. 언어 선택기가 i18next의 현재 언어를 변경한다.
2. `Header`와 `Footer`가 동일한 번역 리소스에서 공통 문자열을 다시 렌더링한다.
3. `SlotButton`이 현재 언어와 저장된 `nameKo`, `nameEn`, `nameJa`에서 표시 이름을 계산한다.
4. 번역 이름이 없을 때는 기존 포매터의 한국어 폴백 규칙을 유지한다.

## 오류 및 호환성

- 번역 리소스의 언어별 키 구조는 동일하게 유지한다.
- 기존 `EquipItem` 형식과 직렬화 형식은 변경하지 않는다.
- 아이템 이미지 조회에는 계속 `nameKo`를 사용하므로 Cloudinary 경로에는 영향이 없다.
- 시각적 텍스트 배치와 반응형 레이아웃은 변경하지 않는다.

## 검증

- i18n 리소스 키 동등성 테스트가 새 키를 포함해 통과해야 한다.
- 아이템 포매터 테스트로 한국어, 영어, 일본어의 주 표시 이름과 폴백을 확인한다.
- 컴포넌트 테스트로 `SlotButton`의 언어별 접근성 이름을 확인한다.
- 390x844 모바일 뷰포트에서 언어 전환 후 푸터, 내비게이션, 얼굴 소품 선택 이름을 확인한다.
- 전체 `npm test`, `npm run lint`, `npm run build`를 실행한다.

## 완료 기준

- 영문 모드에서 공통 링크와 선택 아이템 이름에 한국어가 고정 노출되지 않는다.
- 일문 모드에서 공통 링크와 선택 아이템 이름에 한국어가 고정 노출되지 않는다.
- 한국어 모드와 기존 저장 데이터의 동작이 유지된다.
- 실제 사진 파일 선택은 인앱 브라우저 제한으로 별도 수동 병합 게이트에 남긴다.
